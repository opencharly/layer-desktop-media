### Block 2 (A2/B12/R2 — the structural gate) — in-tree schema proof + org-wide routing

**The `skill:` entity validates against the canonical CUE schema, in-tree, right now.**
`spec/schema/skill.cue` defines `#Skill`; the gate `charly box validate` cannot run
because of the org-wide config-`version:` removal (below), but the schema that validates a
`skill:` node CAN be run directly against this head. Extract the entity from this PR's
`charly.yml`, conjoin it with the canonical `#Skill`, and `cue vet -c`:

```bash
$ mkdir /tmp/cuecheck && cd /tmp/cuecheck
$ { echo "package skillcheck"; echo; cat <spec>/schema/skill.cue; } > skill.cue
$ python3 - <<'PY'   # emit the entity from THIS PR's charly.yml as CUE
import yaml
src=yaml.safe_load(open('charly.yml'))
sk=src['desktop-media-skill']['skill']
def q(s): return '"'+s.replace('\\','\\\\').replace('"','\\"').replace('\n','\\n')+'"'
print(f'package skillcheck\n\nentity: #Skill & {{')
print(f'\tname:        {q(sk["name"])}')
print(f'\tfamily:      {q(sk["family"])}')
print(f'\towner:       {q(sk["owner"])}')
print(f'\tdescription: {q(sk["description"])}')
print(f'\tcontent:     {q(sk["content"])}')
print('}')
PY
$ cue vet -c .
$ echo "valid exit=$?"
valid exit=0
```

The entity is concrete and satisfies every `#Skill` constraint (`name`/`family`/`owner`
match `^[a-z][a-z0-9-]*$`, `description`/`content` non-empty). A negative control proves
the check can FAIL — a `name: "Bad_Name"` entity errors:

```
$ cue vet -c .
badentity.name: invalid value "Bad_Name" (out of bound =~"^[a-z][a-z0-9-]*$"):
    ./skill.cue:22:24
    ./bad.cue:4:15
$ echo "negative exit=$?"
negative exit=1
```

This is the structural gate for a `skill:` entity, run on this head, with a positive and a
negative control — not a YAML parse.
